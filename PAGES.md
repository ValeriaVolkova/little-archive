# GitHub Pages для Little Archive

Git-репозиторий веб-приложения находится в папке `web`. Workflow должен находиться в `.github/workflows/pages.yml` на верхнем уровне репозитория GitHub. Ветка публикации — `main`.

## Подтверждение первой публикации

1. Указать точный URL репозитория GitHub для веб-версии или подтвердить создание отдельного репозитория `little-archive` и его владельца. На бесплатном тарифе для Pages нужен публичный репозиторий. Публичный Git-репозиторий также делает доступными его исходники и историю, отдельно от содержимого Pages. Для первой публикации в новый публичный репозиторий использовать чистый снимок согласованных файлов, без переноса истории текущей рабочей копии, настроек текущего хостинга и тестовых изображений.
2. Владельцу репозитория открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**. Если политика GitHub требует доступа к Actions или отдельного подтверждения среды `github-pages`, включить доступ или одобрить первый запуск.
3. После успешного запуска взять точный адрес из **Settings → Pages** или из ссылки среды `github-pages` в Actions. Адрес проекта обычно имеет вид `https://ВЛАДЕЛЕЦ.github.io/little-archive/`. Включить **Enforce HTTPS**, если в настройках доступен этот переключатель.

## Что входит в публикацию

Workflow запускает тесты и собирает артефакт из явного списка файлов `dist/`. В список входят рабочие HTML, CSS, JavaScript, манифест, шрифт, лицензии, вендорная библиотека PDF и штатные демонстрационные SVG. ZIP, тестовые изображения и скрипты, конфигурация текущего хостинга и остальное содержимое репозитория в артефакт не входят.

У каждого проекта Pages свой Service Worker и отдельный кэш оболочки. При изменении файлов версия этого кэша обновляется автоматически. Исходный `dist/sw.js` и данные браузера при упаковке не меняются. GitHub Pages с новым доменом получит отдельный локальный архив. Для переноса с прежнего адреса сохранить ZIP через старый сайт и импортировать на новом. Для тестирования лучше использовать тестовый архив.

Важно при выборе адреса. Разные пути на одном `ВЛАДЕЛЕЦ.github.io` разделяют IndexedDB и localStorage по домену. Для двух независимых копий Little Archive нужны разные домены или разные профили браузера.

## Следующие обновления

Каждое обновление `main` запускает тесты, создаёт артефакт заново и публикует его по прежней ссылке при успешной проверке. Ручной повтор доступен в **Actions → Publish Little Archive to GitHub Pages → Run workflow**. Если Safari показывает прежнюю версию, закрыть вкладки Little Archive и открыть ту же ссылку. Очищать данные сайта для обновления не нужно.

Локальная проверка из `web`:

```text
npm test
node scripts/package-pages.mjs .artifacts/pages-review
```

Используйте новый каталог для каждого прогона упаковки. Скрипт проверяет пути относительно подпапки проекта, установку кэша и то, что Worker не очищает кэши соседних сайтов.

Чтобы проверить реальную загрузку артефакта под `/little-archive/` и сохранение данных, задайте `BROWSER_PATH` как в [инструкции тестирования](IPHONE-CHECK.md) и выполните `npm run test:storage-browser -- .artifacts/pages-review`. Этот прогон использует только локальный тестовый сервер, временный профиль и синтетическое фото.
